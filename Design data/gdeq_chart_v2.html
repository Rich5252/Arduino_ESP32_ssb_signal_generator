Group-delay equalizer: refit against real hardware, extended to 8 kHz

Same TFA sweep as before, re-read with a smoothing window sized for real (noisier) hardware data instead of the LTspice-era default — this corrects the previous chart's headline dispersion figures. New coefficients fit directly against the measured analog curve, target band widened 100–4300 Hz → 100–8000 Hz to match observed freq_dev excursions.

Correction to the previous chart

The first pass at this data used a 31-point (~700 Hz) smoothing window, which turned out to be too fine for this denser, noisier real-hardware sweep — it reported 146.1→147.2 µs p-p ("no improvement") over 100–4300 Hz. A wider window (181 points, chosen from a convergence check), applied to the exact same measured curves, gives 36.6→14.3 µs p-p — a real ~61% reduction, close to the original LTspice prediction (41.1→13.7 µs). The equalizer's old coefficients were doing close to what they were designed to do all along, within their own fit band. This chart uses the corrected (181-point) smoothing throughout.

Reading this result

Over the new 100–8000 Hz band, the analog filter alone measures 71.2 µs p-p. The old coefficients (fit only to 4300 Hz) blow up to ~450–580 µs past that point — confirming a real refit was needed, not just a wider claimed range. The new coefficients (a1=0.026173, a2=0.236810), fit directly against this measured analog curve, predict 18.5 µs p-p across the full extended band (~3.9×), with ~125 µs mean added delay (2.006 samples @ 16 kHz).

Still open: this is a better-fitted equalizer, not a re-validated one. A separate, independently-confirmed real-hardware IMD test (documented in group_delay_fit_notes.md) found the old coefficients made 3rd-order two-tone IMD 6–10 dB worse, for reasons beyond narrowband delay flatness — the all-pass structure can't touch this filter's real insertion-loss penalty, and a separate envelope-interpolation confound was never fully ruled out. This refit answers two of that finding's four suspected causes (the narrow fit window, and possibly the DC-bias measurement inconsistency the Hi-Z buffers were added to fix) but not the other two. g stays off by default until the same IMD delay-sweep procedure is re-run against these new coefficients.
